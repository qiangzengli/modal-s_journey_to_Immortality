# 《逆命录》地图版 MVP

这是 [全员 Agent 修仙沙盒项目分享文档](../docs/全员Agent修仙沙盒-项目分享文档.md) 中“地下坊市的一场机缘”的独立试玩切片。主界面是一张可探索的 3D 地图，包含地下坊市、黑风林、玩家模型、8 名坊市人物与 4 名可斗法的林中散修。场景及人物由 Three.js 几何体原创搭建，不使用仓库其他页面或 Unity 项目的资产。

## 启动

需要 Node.js 22.9 或更新版本，以及支持 WebGL 的浏览器。

```bash
cd mvp
npm ci
npm start
```

打开 `http://127.0.0.1:4177`。默认使用离线规则解析，完整玩法可运行。服务仅监听本机地址。存档位于 `mvp/.data/save.json`；“行囊 → 重开此局”可开始新局。当前只有一个共享存档，建议只在一个标签页游玩；旧页面提交行动时会先同步最新局势，避免重复扣费。已有 v2 存档会自动补齐新增字段并保留进度。

要使用本机 Ollama 模型，先确认 `ollama list` 中有 `qwen2.5-coder:14b`，启动 Ollama 服务，然后运行：

```bash
cd mvp
npm run start:ollama
```

如果使用其他兼容 OpenAI Chat Completions 的模型服务，可自行设置 `LLM_BASE_URL`、`LLM_MODEL`，云端服务还可设置 `LLM_API_KEY`。例如：

```bash
LLM_BASE_URL=http://127.0.0.1:11434/v1 LLM_MODEL=qwen2.5:0.5b npm start
```

模型响应默认最多等待 30 秒，可用 `LLM_TIMEOUT_MS` 调整。底部“心念传音”支持问计和行动：提问直接交给模型结合当前局势回答；明确的中文行动先由规则解析器处理，无法识别的行动表达再由模型解析。不能映射为行动的表达会转为问计。问计超时、断线或回答无效时，显示明确来源及已知线索；行动解析失败会提示重试，不消耗资源。模型也参与手札线索解读和人物多轮交谈，不能自行改写灵石、物品或战斗结果。人物的世界行动仍按状态规则结算。

### 本机模型失败时使用 DeepSeek

将 `.env.example` 复制为 `mvp/.env.local`，在本地填写 `LLM_FALLBACK_API_KEY`。`npm start` 和 `npm run start:ollama` 都会读取该文件；已有环境变量优先。`.env.local` 已被 Git 忽略，密钥只在服务端使用，不会发给浏览器或写入存档。修改配置后重启服务。

每次生成优先使用本机模型；连接失败、超时、HTTP 错误、空回答或内容校验不通过时，自动尝试 `deepseek-v4-flash`。备用请求单独使用 `LLM_FALLBACK_TIMEOUT_MS`（默认 30 秒）。此逻辑覆盖心念传音、行动解析、手札和人物交谈；模型回答旁显示实际使用的模型名。启用备用服务后，失败请求所需的游戏公开局势、输入及最近交谈会发往 DeepSeek。两个服务都失败时仍返回明确的规则线索或错误提示，不执行未经确认的状态修改。新的生成请求继续优先尝试本机，已缓存的手札回答沿用原来源。

## 地图操作

- 点击道路和空地寻路，或用 WASD / 方向键沿地图坐标轴移动。默认视角下，W / ↑ 朝左上、S / ↓ 朝右下，A / ← 朝左下、D / → 朝右上；单键即可沿道路移动，双键组合不会加速。建筑、摊位、树木和岩石会阻挡通行。滚轮缩放，Q / E 旋转视角，旋转不会改变按键对应的地图方向。右下角按钮可缩放、旋转和复位，小地图可点击导航。
- 点击人物模型，角色会走近；靠近人物、地点或界门时也可按 F，或点击屏幕上的交互提示。人物卡显示当前问候、境界、关系、公开往事，以及行动代价和未满足的条件。行动结果显示在交互卡和人物旁，可直接接着追踪下一步；点击“探问近况”会留下正式交谈记录，AI 多轮问答另外保留在当前页面。
- 在黑风林点击“灵草坡”采药，“天雷阵位”布阵或伏击，“听雨亭”调息或服丹筑基。所有关键行动都有地图入口；左侧“行动”浮层中选择可用行动，角色会自动走到现场并执行。
- 左上修行手札可选择交易、借势或夺宝路线，路线选择会保留。点击一次追踪便会经过界门，继续走到最终目标。途中可用方向键、Esc 或“停止”取消，改选目标会取消旧目标及其待执行行动。取得丹药后，未做的前置会标记为不再需要。
- 沈秋的交互卡提供报价和筹码选择；可多次尝试议价，但报价过低可能降低信任。货道证词、真丹鉴定需要实际获得后才能作为筹码。
- 点击界门、门另一侧的道路，或沿主路走过界门，可在坊市与黑风林之间移动。过门后从门边继续行走，镜头平滑跟随；挡住玩家或当前交互人物的建筑会淡化，方便观察。
- 地图左侧的“机缘、行囊、人物、行动、邸报”会打开浮层；再次点击或按 Esc 关闭。地图始终是主画面。
- 地图底部“心念传音”可提问，如“灵石不够怎么办？”“买筑基丹还差多少灵石？”。回答显示在输入框上方，可连续追问或点击建议追踪目标。问答不扣资源、不推进时间；当前页面保留最近问答，发送最近六条作为上下文，可点击“清空问答”。模型未连接、超时或回退时会明确标记。局势或路线改变后，旧建议按钮收起。
- 也可直接写行动计策，如“请白芷验丹”或“我拿货道证词压价，出价 200 灵石买丹”，一次执行一个行动。Enter 提交，Shift+Enter 换行。系统先解析意图，再走到对应人物或地点执行；跨区也会连续完成，途中取消不会执行原定行动。询问条件、商量或否定行动的表达会先进入问计，避免把问题中的行动关键词直接执行。
- 行动次数不限，旧存档中耗尽的行动点也不再限制操作。灵石、物品和事件前置条件照常生效；右上角“推进一旬”会结算人物行动和事件，以可关闭、自动收起的小型旬报展示新动向，详细因果可展开邸报查看。资源增减会浮动提示，持丹者有金色光环，采药和布阵会改变地图状态。

## AI 手札与人物交谈

手札会根据当前路线、资金缺口、已经取得的线索、伤势和近期事件生成解读，建议可以追踪的已有目标。目标进度与资金等事实仍由规则显示；AI 文字是建议，不是任务完成凭证。切换路线或实际行动改变局势后会重新解读，同一局势复用结果，避免反复调用模型。可展开“追问这条线索”输入顾虑，或点击模型给出的追问。

到人物身边后，可以在交互卡输入自己的话，也可点击“探问近况 · 人物交谈”。白芷、宁素、徐宁等人会结合角色关切、公开往事和最近六条交谈回应、追问并推荐已有行动。因此鉴丹、货道调查、合资履约等流程可以通过自然语言商量；原有执行按钮仍可直接使用，AI 不增加额外任务门槛。推荐按钮显示代价，点击后仍走原有寻路与服务器结算。AI 问答不扣费、不推进时间、不获得证据、不改变好感、任务条件或奖励。“探问近况”沿用原有 ask 行动记录一次正式交谈，再由 Agent 延续话题。

人物交谈记录在当前页面中保留，关闭人物卡再打开可继续，刷新页面会清空本页对话；已执行行动产生的正式往事仍随原存档保存。地图散修目前沿用观察与斗法流程，这轮 Agent 交互覆盖八位剧情人物。

运行 `npm run start:ollama` 可使用本机 `qwen2.5-coder:14b` 进行真实生成；也可沿用上面的模型环境变量。界面会显示“AI · 实际模型名”或明确标记“未连接模型 / 模型暂未回应 · 已知线索”。模型加载、超时或返回非法内容时仍可操作地图和原有行动，规则线索作为回退。模型文本可能判断失误，界面的资金、条件与实际结算是事实依据。

`POST /api/agent` 是不写存档的推演请求：

```json
{"mode":"guide","route":"trade","text":"灵石不足时如何筹资？","expectedRevision":0}
```

人物交谈用 `mode: "dialogue"`，加 `personId`、非空 `text` 与可选 `history: [{role: "user" | "assistant", text}]`。问话最多 280 字，历史最多六条、每条 400 字。响应包含 `title`、`text`、`followUps`、经校验的 `suggestions`、`source`、`reason?`、`modelName`、`revision`。模型只能选现有候选 ID；本地模型返回完整按钮名时只按精确匹配归一到白名单，实际行动对象由服务器构造，模型不能提供状态补丁。输入非法返回 400；起始版本过期或模型等待期间局势变化返回 409 和最新 `view`；推演不占用行动锁。最多两个生成请求并行，手札缓存最多 24 个上下文，超时沿用 `LLM_TIMEOUT_MS`。

## 试玩目标

沈秋持有一枚筑基丹，开价 280 灵石。你初始有 180 灵石、1 株灵草和 1 张天雷符。可尝试：

1. **交易：**请白芷验丹 → 找徐宁合资 → 卖灵草 → 买丹。合资承诺仍须履行。
2. **举报：**找宁素取得货道证词 → 向陆执事举报 → 推进一旬 → 从公售中买丹。
3. **伏击：**约沈秋出城 → 穿过界门入林 → 布下天雷符 → 推进一旬 → 伏击。会付出气血和声望代价。
4. **传闻：**向青闻买空白鉴定印 → 伪造有毒鉴定 → 推进时间，观察人物的连锁反应。

取得丹药后可前往黑风林听雨亭，气血至少 60 时可服丹筑基。气血不足可花 10 灵石调息，最多恢复 30 气血；满血不能重复收费。青闻处可用 35 灵石购买天雷符。筑基后仍能继续游历，欠款和夺丹追查不会因突破消失。

## 黑风林斗法与储物袋

点击地图上的散修，或从“人物 → 黑风林散修”选择目标，角色会走到其身边。观察修为、气血、携带物品和败退代价，再选择“发起斗法”。开战时双方进入独立的 3D 斗法空间，主地图位置和镜头保留，按钮显示在下方。结束后返回林道原位置，储物袋仍留在主地图。散修不会在玩家阅读界面时自动攻击。

出招按蓄力、命中、敌方回应依次播放；命中时显示伤害浮字、受击动作和轻微震屏，动画结束后更新回合与结算面板。普通攻击是月牙剑光，凝气诀是蓝色气弹，疾风剑诀是三道风刃，离火诀是火球与升腾烈焰，惊雷诀是分叉落雷，回春术是花阵与绿色灵光。防御、两种丹药、缚灵阵、雷火阵和逃跑也有独立表现；防御护罩会保持到对手出招结束。敌方剑修、药修、火修、阵修使用对应风格的特效。系统开启“减弱动态效果”时，减少粒子与人物位移并关闭震屏。特效仅用于表现，不影响伤害、消耗或随机结果。

| 散修 | 特点 | 主要战利品 |
| --- | --- | --- |
| 罗槐 · 炼气六层 | 进攻、重击、守势交替，适合首次挑战 | 青锋剑、疾风剑诀、回春丹、灵草 |
| 苏芩 · 炼气八层 | 会在回合中疗伤 | 青藤杖、回春术、缚灵阵盘、大量灵草 |
| 裴烬 · 炼气九层 | 以蓄力重击起手 | 赤炎剑、离火诀、聚气丹、雷火阵盘 |
| 墨迟 · 炼气圆满 | 防御更高，重击更频繁 | 雷纹刃、惊雷诀、两类阵盘 |

- 每次选择结算玩家行动，再结算敌人行动。敌人若先被击败，不会反击。界面提前显示敌方意图：重击可防御或打断，守势时可回气、服丹。
- **普通攻击**回复最多 5 真气；**凝气防御**回复最多 8 真气并减少本回合受到的伤害 65%。每场开始时真气为 40，气血沿用当前伤势。
- **功法**消耗真气并有独立冷却。初始掌握凝气诀，其他功法需获得秘籍后在行囊研习。功法分伤害、治疗两类，武器增强普攻与伤害功法，筑基后额外增加 5 点基础威力。
- **灵丹**和**阵盘**使用后消耗一件并占用回合。回春丹恢复最多 35 气血，聚气丹恢复最多 22 真气；缚灵阵造成伤害并打断当前敌方行动，雷火阵造成较高伤害。阵盘和惊雷诀无视基础防御，敌人的护体守势仍会减伤。
- **逃跑**成功率按对手为 70% / 60% / 50% / 40%。失败会遭到反击，成功保留伤势和物品、没有战利品。再次挑战时敌人满血。
- **败退**损失当前灵石的 10%（向上取整），以 25 气血脱身，物品和已修功法保留。气血不足 20 时无法挑战，可服丹或去听雨亭调息。
- **胜利**后散修退场，储物袋留在原地。可立即领取，也可稍后返回；每个储物袋仅可领取一次。拾取后自动打开行囊，可装备武器、研习秘籍、服用回春丹；灵草并入原有资源，可回坊市出售。四位散修当前每局只可击败一次，不自动刷新。
- 新局及旧存档首次升级会获得旧铁剑、凝气诀、2 颗回春丹和 1 颗聚气丹。已消耗物品不会因重启补发。战斗回合、气血、真气、冷却和未拾取的储物袋随存档保存；刷新或重启可继续。战斗中不可移动、场外服丹或推进旬数。

“邸报”记录事件及其缘起。当前人物策略和斗法 AI 由状态规则驱动，这还不是能自主规划任意目标的通用 Agent。地图只包含两处区域，人物模型采用简洁低多边形风格，斗法为单人对单人，尚无夺舍或魂幡系统。

## 验证

```bash
cd mvp
npm test
```

规则测试覆盖交易履约、举报查封、伏击代价、假消息传播、调息筑基、动态对话、行动预览和路线指引。寻路流程测试覆盖跨区续行、取消、改选目标和路径失败。服务测试使用临时目录，验证意图解析不修改进度、旧存档行动点耗尽时仍可操作、迁移、过期请求拒绝、落盘及重启恢复，不读取正式存档。

需要独立试玩存档时可另启端口：

```bash
PORT=4178 SAVE_PATH=/tmp/niminglu-playtest.json npm start
```

服务提供 `/api/state`、`/api/intent`、`/api/action`、`/api/command`、`/api/advance`、`/api/reset` 给本地页面使用。`/api/intent` 接受 `{text, expectedRevision, route?, history?}`，其中 `route`、`history` 的格式及限制与 `/api/agent` 相同。响应包含当前 `view`、`modelName`、`parserSource`，以及互斥的 `action`（明确行动）或 `reply`（结构同 `/api/agent` 的问答结果）。该接口不修改进度、不占行动锁；起始版本过期或生成期间局势变化返回 409 和最新 `view`。收到 `action` 后，页面到达目标再提交 `/api/action`。原 `/api/command` 保留直接解析并执行的兼容行为。POST 可携带当前 `view.revision` 作为 `expectedRevision`；过期提交不执行行动。`view.ap` 为 `null`，表示不限行动次数，只有 `/api/advance` 会推进旬数。


斗法接口沿用本机服务的 Host/Origin 校验、JSON 请求和 `expectedRevision` 防重复机制。输入非法返回 400；状态过期返回 409 与最新 `view`，不执行行动。成功后先落盘再返回结果。

- `POST /api/combat`：`{type: "start", enemyId}` 发起斗法；`{type: "turn", move, skillId?, itemId?}` 结算一个回合，`move` 为 `attack` / `skill` / `guard` / `item` / `escape`；`{type: "claim", enemyId}` 拾取已击败者储物袋；`{type: "leave"}` 关闭已结束的战斗。
- `POST /api/inventory`：`{type: "equip" | "learn" | "use", itemId}`，分别装备武器、研习秘籍、场外服用回春丹。
- `view` 新增 `roamers`、`inventory`、`skills`、`weapon` 和 `battle`。回合数、真气、冷却、血量和随机结果由服务端管理；客户端仅发出选择。老接口和 v2 存档兼容，新增状态保存在 `exploration` 中。

目前为本机单人玩法：服务端校验所在区域及战斗状态，地图坐标与走近目标由客户端表现层负责，不提供联网游戏的坐标防作弊。普通游玩退出斗法会回到进入前的位置；战斗中刷新页面后，会从对手附近恢复地图位置。

斗法测试覆盖真气、冷却、反击、防御、逃跑成功与失败、丹药和阵盘消耗、败退、战利品唯一领取、装备研习及战斗期间行动限制。服务测试额外验证重复回合拒绝和战斗中途重启恢复。

特效测试使用真实 Three.js 对象，覆盖全部功法、灵丹、阵盘及基础动作的动画变换、延迟播放、几何与材质释放，以及减弱动态模式，避免连续交锋后累积场景对象。
