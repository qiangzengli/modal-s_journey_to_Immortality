# 《逆命录》游戏指南

新开局扮演韩立，从七玄门入门考核开始，依次经历神手谷、墨大夫与小绿瓶、七玄门之围、嘉元城墨府、太南小会。第一卷「七玄问道」有 6 章、17 段主线、3 条故人支线，新增 4 张独立地图和 7 位人物。随后继续黄枫谷入门、百药园潜修、血色禁地采药、筑基与拜师李化元。

已有存档保留资源、装备、历史与当前位置，公开人物身份升级为原著人物，继续接入黄枫谷主线。体验新第一卷需在游戏中选择「重开此局」并确认；这会覆盖当前存档。需要同时保留旧旅途时，用独立端口和存档启动：

```sh
PORT=4178 SAVE_PATH=/tmp/niminglu-qixuan.json npm start
```

所有模型调用仍固定使用 DeepSeek `deepseek-v4-flash`。第一卷任务由服务端规则结算，人物对话与自主决策由模型结合当前经历生成；对话本身不发放剧情奖励。地图和人物由 Three.js 程序化绘制。


## 启动

需要 Node.js 22.9 或更新版本，以及支持 WebGL 的浏览器。

```bash
npm ci
npm start
```

打开 `http://127.0.0.1:4177`。配置模型后，DeepSeek 驱动人物交谈、自主行动、委托和斗法战术；未配置时暂停人物自主决策，仍可移动、交易、战斗及使用“静修一旬”结算灵圃与已签约定。离线时对手会明确标注“基础应对”。服务仅监听本机地址。存档位于 `.data/save.json`；“行囊 → 重开此局”可开始新局。当前只有一个共享存档，建议只在一个标签页游玩；旧页面提交行动时会先同步最新局势，避免重复扣费。已有 v2 存档会自动补齐新增字段并保留进度。

模型统一使用 DeepSeek 的 `deepseek-v4-flash`。首次配置时，在项目根目录执行：

```bash
cp .env.example .env.local
```

在 `.env.local` 填入自己的 `LLM_API_KEY`，再运行 `npm start`。服务端将所有模型调用固定到 `https://api.deepseek.com` 的 `deepseek-v4-flash`；旧的 `LLM_MODEL`、`LLM_BASE_URL` 和 `LLM_FALLBACK_*` 配置不再生效。无需启动本机模型。

模型响应默认最多等待 30 秒，可用 `LLM_TIMEOUT_MS` 调整。底部“心念传音”支持问计和行动：提问直接交给模型结合当前局势回答；明确的中文行动先由规则解析器处理，无法识别的行动表达再由模型解析。不能映射为行动的表达会转为问计。问计超时、断线或回答无效时，显示明确来源及已知线索；行动解析失败会提示重试，不消耗资源。模型也参与手札线索解读和人物多轮交谈，不能自行改写灵石、物品或战斗结果。人物何时调查、交易、赴约或提出委托由 Agent 选择，资源和战果由规则结算。

`npm start` 读取 `.env.local`，已有环境变量优先；修改配置后需重启服务。`.env.local` 已被 Git 忽略，密钥只在服务端使用，不会发给浏览器或写入存档。心念传音、行动解析、手札和人物交谈都直接调用 DeepSeek，不需要安装或启动本机模型。请求携带游戏局势、人物自身目标与记忆、输入及最近交谈，模型回答旁显示实际使用的模型名。DeepSeek 超时、连接失败或回答未通过校验时显示规则线索或错误提示，不切换到本机模型。

## 地图操作

- 点击道路和空地寻路，或用 WASD / 方向键沿地图坐标轴移动。默认视角下，W / ↑ 朝左上、S / ↓ 朝右下，A / ← 朝左下、D / → 朝右上；单键即可沿道路移动，双键组合不会加速。建筑、摊位、树木和岩石会阻挡通行。滚轮缩放，Q / E 旋转视角，旋转不会改变按键对应的地图方向。右下角按钮可缩放、旋转和复位，小地图可点击导航。
- 点击人物模型，角色会走近；靠近人物或地点时也可按 F，或点击屏幕上的交互提示。人物卡显示当前问候、境界、关系、公开往事，以及行动代价和未满足的条件。行动结果显示在交互卡和人物旁，可直接接着追踪下一步；人物交谈由 Agent 回应并存入该人物的独立记忆；刷新或重启后继续保留最近对话。
- 在太岳山脉点击“灵草坡”采药，“天雷阵位”布阵或伏击，“听雨亭”调息或服丹筑基。所有关键行动都有地图入口；左侧“行动”浮层中选择可用行动，角色会自动走到现场并执行。
- 左上修行手札由 DeepSeek 根据当前人物、资金、证据和丹药去向，设计多条取丹方案。方案名称、报价、行动顺序和取舍由模型生成，不再有固定的三类路线。选择方案后点击“执行”只完成当前一步，途中可用方向键、Esc 或“停止”取消。局势改变后会重新规划剩余步骤，取得丹药后显示目标已完成。
- 许掌柜的交互卡提供报价和筹码选择；可多次尝试议价，但报价过低可能降低信任。货道证词、真丹鉴定需要实际获得后才能作为筹码。
- 打开“天下”，选择任意修为允许的区域，直接传送到该图落点。跨图追踪人物或地点会先传送，再在当地走近；不经过中间地图、不扣灵石、不推进旬数。走到边界不会自动换图；挡住玩家或当前交互人物的建筑会淡化，方便观察。
- 地图左侧的“天下、机缘、行囊、门派、人物、行动、邸报”会打开浮层；再次点击或按 Esc 关闭。地图始终是主画面。
- 地图底部“心念传音”可提问，如“灵石不够怎么办？”“买筑基丹还差多少灵石？”。回答显示在输入框上方，可连续追问或点击建议追踪目标。问答不扣资源、不推进时间；当前页面保留最近问答，发送最近六条作为上下文，可点击“清空问答”。模型未连接、超时或回退时会明确标记。局势或已选方案改变后，旧建议按钮收起。
- 也可直接写行动计策，如“请马师兄验丹”或“我拿货道证词压价，出价 200 灵石买丹”，一次执行一个行动。Enter 提交，Shift+Enter 换行。系统先解析意图，再走到对应人物或地点执行；跨区也会连续完成，途中取消不会执行原定行动。询问条件、商量或否定行动的表达会先进入问计，避免把问题中的行动关键词直接执行。
- 行动次数不限，旧存档中耗尽的行动点也不再限制操作。灵石、物品和事件前置条件照常生效；前台探索约每 90 秒由人物自主决定一次行动；右上角“听候风声”可主动推演一次，以可关闭、自动收起的小型旬报展示新动向，详细因果可展开邸报查看。资源增减会浮动提示，持丹者有金色光环，采药和布阵会改变地图状态。

## 众生自主演化

所有 25 名现有人物都有独立目标、性格、资产、近期交谈和记忆。世界 Agent 在一批模型请求中为每个人分别决策；各人物的感知分区提供，提示约束其只使用自身信息，不是每名人物各发一次 HTTP 请求。行动范围包括观察、区域内游历、符合前置条件的调查/传讯/交易/赴约，以及提出委托、开府援助和结局后的生计安排、救治、留史。模型不能生成任意可执行代码或未实现的能力。

- **探索节奏**：前台每约 90 秒推演一旬；打开人物或地点交互、导航、输入、斗法、隐藏页面时暂停自动演化。可随时暂停/继续，也可用“听候风声”单步，不再依赖玩家重复点“结束回合”。后台不补算离线时间，多标签共用一个时钟。
- **行为有后果**：移动会改变地图位置；调查、借贷、买丹等会改变真实世界与资产。人物会记住承诺、拒绝和委托交付，结合自身利益调整目标。主线取丹的资源与结局规则保留，但 NPC 决定及其执行时机不再按旬数写死。
- **委托有资金来源**：NPC 自行决定是否发出委托，以及名称、缘由、数量和报价。目前支持收购 1～2 株灵草，报酬 10～60 灵石；先从其自有灵石托管。每人最多一份活跃委托，全世界最多六份。到场可接受、交付或婉拒，六旬期限结束退款，奖励仅可领取一次。散修的托管资金会从其储物袋现金中扣除；委托人败退时撤回尚未完成的委托，退回的资金计入可拾取储物袋。
- **模型失败**：自主决策整批无效则世界保持原状，不换成固定脚本。界面显示失败原因，可重试或选择“静修一旬”只结算灵圃、恢复与既有约定。模型等待不锁住玩家探索；期间发生新操作会废弃旧决策，避免覆盖新进度。

人物面板首先展示 Agent 当前动向、交谈与委托；原有交易和事务按钮保留为可靠的执行入口。当前动态任务范围仍是灵草交付，尚不支持模型任意创造功法、跨地图任务链或新的战斗规则。

接口均使用本机 Host/Origin 校验与 JSON：

| 接口 | 输入与行为 |
| --- | --- |
| `POST /api/world/pulse` | `{engaged:boolean}`，前台每 4 秒发送，返回最新 `view` 与 `clock`；空闲累计时间达到阈值才异步生成 |
| `POST /api/world/step` | `{expectedRevision}`，主动推演一次，返回 `advanced`、`clock`、`view`；重复请求共享当前生成 |
| `POST /api/world/control` | `{paused:boolean, expectedRevision}`，持久保存暂停偏好 |
| `POST /api/npc/dialogue` | `{personId,text,expectedRevision,plan?}`，以服务端历史交谈，成功保存记忆并返回新版本 |
| `POST /api/contracts` | `{type:"accept"\|"deliver"\|"decline",offerId,expectedRevision}`，按实际资金与物品完成契约 |

除心跳外以上新接口强制校验 `expectedRevision`，过期返回 409；非法人物、异地交谈或越权动作返回 400。所有写操作原子落盘后才公布新状态。新增 `society` 存档字段自动迁移，旧资源与进度保留。

测试覆盖全员候选校验、记忆分区、资金托管/退款/重复领取、散修现金守恒、模型战术、自动时钟去重、暂停/超时/迟到结果、并发行动与重启恢复。

## AI 手札与人物交谈

手札的目标是取得筑基丹。DeepSeek 自由组合现有行动，提出方案名称、完整行动序列、原因和风险，通常给出两至四个不同方案；已经能直接参加公售等局势可以只给一条。不是给预设路线换名称，也不会用额外购物凑方案数。可展开“提出偏好 · 重新设计”，输入“不欠人情”“不动武”等要求；偏好在本机保留。点击刷新按钮会真正重新请求模型。

每条方案在游戏副本中按真实行动规则逐步试算，校验资金、证据、地点、人物动向及最终是否取得丹药。跨区先传送、落地后自动寻路；生成方案不会扣资源、推进时间或改写存档。方案会展示预计剩余灵石、气血、声望、欠款与等待旬数，“机缘”面板可查看完整步骤。玩家每次只执行一步，之后按新局势重新规划。旧方案在等待新结果时立即失效，模型生成期间仍可探索。

生成失败不会恢复固定三选一；手札明确提示重试，地图原有行动仍可使用。取丹规划器可以自由组合和报价，不能创建引擎没有实现的物品、NPC 转让或取丹机制。动态委托由独立的人物决策 Agent 提出，当前支持灵草换灵石。规划器不能假设其他人物将来必定借钱、赴约或查封；只有已发生的事实才可作为可执行方案的依据。若丹药已经被他人买走且没有可执行的转让方式，会如实说明，不编造可用路线。

到人物身边后，可以在交互卡输入自己的话，也可点击“探问近况 · 人物交谈”。马师兄、萧翠儿、吴风等人会结合角色关切、公开往事和最近六条交谈回应、追问并推荐已有行动。因此鉴丹、货道调查、合资履约等流程可以通过自然语言商量；原有执行按钮仍可直接使用，AI 不增加额外任务门槛。推荐按钮显示代价，点击后仍走原有寻路与服务器结算。AI 交谈本身不扣游戏资源、不推进时间、不发放证据或奖励，但会写入该人物的记忆，影响其后续自主选择。“探问近况”沿用原有 ask 行动记录一次正式交谈，再由 Agent 延续话题。

18 位剧情人物和 7 位未败退游历修士都可交谈。每人保留最近 10 条对话、16 条记忆和当前目标；刷新页面、重启服务后仍可延续。人物间不共享私人对话记录。服务端使用保存的对话历史，忽略客户端提交的伪造历史。底部问计属于玩家的只读推演，仍仅保留本页记录。

完成 DeepSeek 配置后运行 `npm start` 即可生成回答。界面会显示“AI · deepseek-v4-flash”或明确标记“未连接模型 / 模型暂未回应 · 已知线索”。模型超时或返回非法内容时仍可操作地图和原有行动，规则线索作为回退。模型文本可能判断失误，界面的资金、条件与实际结算是事实依据。

`POST /api/agent` 是不写存档的推演请求：

```json
{"mode":"guide","plan":"采草换石后议价","text":"灵石不足时如何筹资？","expectedRevision":0}
```

兼容接口 `/api/agent` 可以用 `mode: "dialogue"` 做不落盘的角色推演；页面实际交谈改用 `POST /api/npc/dialogue`，参数为 `{personId, text, expectedRevision, plan?}`。真实模型回应成功后会保存该人物对话和记忆，增加 revision 并返回最新 `view`；失败回退不写入人物记忆。问话和可选 `plan`（已选方案说明）最多 280 字，历史最多六条、每条 400 字。响应包含 `title`、`text`、`followUps`、经校验的 `suggestions`、`source`、`reason?`、`modelName`、`revision`。模型只能选现有候选 ID；模型返回完整按钮名时只按精确匹配归一到白名单，实际行动对象由服务器构造，模型不能提供状态补丁。输入非法返回 400；起始版本过期或模型等待期间局势变化返回 409 和最新 `view`；推演不占用行动锁。最多两个问答生成请求并行，问计缓存最多 24 个上下文，超时沿用 `LLM_TIMEOUT_MS`。

`POST /api/plans` 是独立的只读规划接口：

```json
{"text":"不借贷，不动武","preferredPlan":"草资换丹","refresh":false,"expectedRevision":0}
```

`text` 最多 280 字，`preferredPlan` 为之前已选方案名（最多 80 字），均可省略。`refresh:true` 跳过缓存，`expectedRevision` 必填。响应包含 `source`、`reason?`、`modelName`、`revision`、`text`、`followUps` 和 `plans`。每条方案含 `id`、`title`、`rationale`、`risk`、`steps`（经校验的行动、地图目标、预计效果和跨区提示）、`forecast`（灵石、气血、声望、欠款和等待旬数）。模型只看到公开局势与行动规则；试算在服务端副本中进行，不持有写存档权限。

每次最多四条方案、每条最多十二步；校验失败时最多反馈模型修正一次。初始版本过期或生成期间状态改变返回 409 和最新 `view`。同局势与偏好的请求合并并缓存，最多 24 份，最多两个规划请求同时进行；每次模型调用沿用 `LLM_TIMEOUT_MS`。无可执行方案、离线、超时或输出无效时 `plans` 为空，不退回固定模板。

## 游戏目标

许掌柜持有一枚筑基丹，开价 280 灵石。你初始有 180 灵石、1 株灵草和 1 张天雷符。可尝试：

1. **交易：**请马师兄验丹 → 找吴风合资 → 卖灵草 → 买丹。合资承诺仍须履行。
2. **举报：**找萧翠儿取得货道证词 → 向叶师叔举报 → 等待他自主决定查验；真正查封后才可从公售买丹。
3. **伏击：**邀请许掌柜出城 → 传送入林准备；他自主决定是否赴约，实际到场后才能伏击。会付出气血和声望代价。
4. **传闻：**向刘靖买空白鉴定印 → 伪造有毒鉴定 → 推进时间，观察人物的连锁反应。

取得丹药后可前往太岳山脉听雨亭，气血至少 60 时可服丹筑基。气血不足可花 10 灵石调息，最多恢复 30 气血；满血不能重复收费。刘靖处可用 35 灵石购买天雷符。筑基后仍能继续游历，欠款和夺丹追查不会因突破消失。

## 太岳山脉斗法与储物袋

“行囊”现在打开人物装备界面。青衣剑修图像旁按兵器、头冠、衣袍、护腕、靴履、腰饰、戒指、法宝分为 8 类、10 个槽位，戒指和法宝各有两槽。当前真实装备为兵器与认主的小绿瓶，其余为后续物品预留的空槽；衣装插画不提供额外战斗属性，也不会自动发放装备。功法放在独立页签中查看。

背包使用叠放网格，每页 20 类物品，无总页数限制；支持名称/说明搜索、类别或槽位筛选，以及类别、威力、数量、名称排序。点击槽位查看候选，点击物品查看属性和与当前兵器的威力差，再确认换装、研习或服丹。桌面端人物与背包并排，窄屏用页签切换。筛选和预览不修改存档；实际操作沿用 `/api/inventory` 的服务端校验。新增装备类型时，需同时补充游戏物品和装备规则，空槽本身不会开放新的战斗机制。

点击地图上的散修，或从“人物 → 游历修士”选择目标，角色会走到其身边。观察修为、气血、携带物品和败退代价，再选择“发起斗法”。开战时双方进入独立的 3D 斗法空间，主地图位置和镜头保留，按钮显示在下方。结束后返回林道原位置，储物袋仍留在主地图。散修不会在玩家阅读界面时自动攻击。

出招按蓄力、命中、敌方回应依次播放；命中时显示伤害浮字、受击动作和轻微震屏，动画结束后更新回合与结算面板。普通攻击是月牙剑光，冰锥术是蓝色气弹，青元剑诀是三道风刃，弄焰诀是火球与升腾烈焰，掌心雷是分叉落雷，回春功是花阵与绿色灵光。防御、两种丹药、缚灵阵、雷火阵和逃跑也有独立表现；防御护罩会保持到对手出招结束。敌方剑修、药修、火修、阵修使用对应风格的特效。系统开启“减弱动态效果”时，减少粒子与人物位移并关闭震屏。特效仅用于表现，不影响伤害、消耗或随机结果。

- 每场开始和每轮结算后，由 Agent 根据人物性格、目标、双方气血/真气与最近交锋选择下一轮进攻、重击、防御或疗伤，不再读取固定轮次连招。仍保留手动回合制操作，尚非实时战斗；模型不可用或战术非法时明确显示“基础应对”，使用试探攻击。
- 每次选择结算玩家行动，再结算敌人行动。敌人若先被击败，不会反击。界面提前显示敌方意图：重击可防御或打断，守势时可回气、服丹。
- **普通攻击**回复最多 5 真气；**凝气防御**回复最多 8 真气并减少本回合受到的伤害 65%。每场开始时真气为 40，气血沿用当前伤势。
- **功法**消耗真气并有独立冷却。初始掌握冰锥术，其他功法需获得秘籍后在行囊研习。功法分伤害、治疗两类，武器增强普攻与伤害功法，筑基后额外增加 5 点基础威力。
- **灵丹**和**阵盘**使用后消耗一件并占用回合。回春丹恢复最多 35 气血，黄龙丹恢复最多 22 真气；缚灵阵造成伤害并打断当前敌方行动，雷火阵造成较高伤害。阵盘和掌心雷无视基础防御，敌人的护体守势仍会减伤。
- **逃跑**成功率按对手为 70% / 60% / 50% / 40%。失败会遭到反击，成功保留伤势和物品、没有战利品。再次挑战时敌人满血。
- **败退**损失当前灵石的 10%（向上取整），以 25 气血脱身，物品和已修功法保留。气血不足 20 时无法挑战，可服丹或去听雨亭调息。
- **胜利**后散修退场，储物袋留在原地。可立即领取，也可稍后返回；每个储物袋仅可领取一次。拾取后自动打开行囊，可装备武器、研习秘籍、服用回春丹；灵草并入原有资源，可回坊市出售。七位斗法对手当前每局只可击败一次，不自动刷新。
- 新局及旧存档首次升级会获得铁剑、冰锥术、2 颗回春丹和 1 颗黄龙丹。已消耗物品不会因重启补发。战斗回合、气血、真气、冷却和未拾取的储物袋随存档保存；刷新或重启可继续。战斗中不可移动、场外服丹或推进旬数。

“邸报”记录事件及其缘起。人物自主策略与斗法战术由模型从合法候选中选择，状态规则负责检验与结算；当前并非能创造任意行动的通用 Agent。地图包含九处独立区域，人物模型采用简洁低多边形风格，斗法为单人对单人，尚无夺舍或魂幡系统。

服务提供 `/api/state`、`/api/intent`、`/api/action`、`/api/command`、`/api/advance`、`/api/reset` 给本地页面使用。`/api/intent` 接受 `{text, expectedRevision, plan?, history?}`，其中 `plan`、`history` 的格式及限制与 `/api/agent` 相同。旧 `route` 字段仅兼容接收，不再影响规划。响应包含当前 `view`、`modelName`、`parserSource`，以及互斥的 `action`（明确行动）或 `reply`（结构同 `/api/agent` 的问答结果）。该接口不修改进度、不占行动锁；起始版本过期或生成期间局势变化返回 409 和最新 `view`。收到 `action` 后，页面到达目标再提交 `/api/action`。原 `/api/command` 保留直接解析并执行的兼容行为。POST 可携带当前 `view.revision` 作为 `expectedRevision`；过期提交不执行行动。`view.ap` 为 `null`，表示不限行动次数，世界 Agent 成功结算及 `/api/advance` 都会推进旬数；后者只结算物理时间与已签约定，不触发任何人物决策。


斗法接口沿用本机服务的 Host/Origin 校验、JSON 请求和 `expectedRevision` 防重复机制。输入非法返回 400；状态过期返回 409 与最新 `view`，不执行行动。成功后先落盘再返回结果。

- `POST /api/combat`：`{type: "start", enemyId}` 发起斗法；`{type: "turn", move, skillId?, itemId?}` 结算一个回合，`move` 为 `attack` / `skill` / `guard` / `item` / `escape`；`{type: "claim", enemyId}` 拾取已击败者储物袋；`{type: "leave"}` 关闭已结束的战斗。
- `POST /api/inventory`：`{type: "equip" | "learn" | "use", itemId}`，分别装备武器、研习秘籍、场外服用回春丹。
- `view` 提供 `roamers`、`inventory`、`skills`、`weapon`、`battle` 和 `combatStats`。回合数、真气、冷却、血量和随机结果由服务端管理；客户端仅发出选择。老接口和 v2 存档兼容，新增状态保存在 `exploration` 中。

人物装备页展示当前基础攻击力、基础法力、真气上限、兵器加成和普攻总威力。基础法力指法术强度，施法消耗的是独立的真气。炼气九层基础攻击力为 14、基础法力为 20；筑基后两者各增加 5，已包含在面板基础值中。真气上限为 40，每次开战补满。

- 普攻 = 基础攻击力 + 兵器加成；青元剑诀 = 基础攻击力 + 20 + 兵器加成。
- 冰锥术、弄焰诀、掌心雷 = 基础法力 + 各自功法加成（5、24、32）+ 兵器加成。
- 回春功 = 基础法力 + 12，不受兵器影响，恢复不超过缺失气血。丹药和阵盘维持固定效果。

属性、功法详情与斗法按钮共同使用服务端计算值。`combatStats` 包含 `baseAttack`、`baseSpellPower`、`realmBonus`（已包含在基础值中）、`weaponBonus`、`maxMana` 和 `basicAttack`；`skills[].scaling` 与 `basicAttack` 都提供 `attribute`、`base`、`skillBonus`、`weaponBonus`、`total`。技能视图的 `power` / `heal` 为未计兵器的当前威力 / 治疗量，展示最终威力使用 `scaling.total`。这些派生属性不写入存档；请求不能覆盖基础属性或总威力。初始伤害维持原平衡，突破后回春功会随基础法力成长。实际伤害仍按防御（掌心雷与阵盘穿防）、±10% 波动、守势减伤结算，不保证等于面板威力。

目前为本机单人玩法：服务端校验所在区域及战斗状态，地图坐标与走近目标由客户端表现层负责，不提供联网游戏的坐标防作弊。普通游玩退出斗法会回到进入前的位置；战斗中刷新页面后，会从对手附近恢复地图位置。

## 小绿瓶与自动灵圃

从「行囊 → 灵植神器」或「行动 → 照看灵圃」前往太岳山脉灵草坡，点击 **认主小绿瓶**。每局只能发现一次，附带一株已栽好的幼苗；新旧存档都可获得，无需重开。瓶身与两座灵畦在地图上可直接点击，灵草会随培养进度长大。拥有神器后，顶部显示灵液或待取产物，点击可返回灵圃。

- **小绿瓶**：每推进一旬凝聚 1 滴灵液，最多存 3 滴。每畦自然生长 1 点，满 4 点成熟；自动浇灌每旬最多用 1 滴，再加 1 点生长。默认已开启自动浇灌、留种续种，首批两旬后成熟。
- **自动培养**：离开林地仍会随游戏旬数生长。每畦成熟产 3 株；开启续种时留 1 株再次栽种，实际 2 株放入灵圃待取。成熟产物不会过期，收取后才进入行囊，可按原规则交给马师兄出售。普通移动、对话、刷新、关闭游戏期间的现实时间不推进培养。
- **手动管理**：可暂停浇灌蓄积灵液，也可用灵液手动催熟。暂停续种后，下次成熟的全部产物待取，灵畦留空；重新种植需行囊灵草 1 株。开启续种只影响下一次成熟，不会凭空给空畦补苗。
- **息壤盆**：在灵圃一次投入 120 灵石炼制，扩建为两畦，所有灵畦每次成熟增产至 4 株；开启续种时每畦实际待取 3 株。新增空畦需要实际栽种。

世界自主推演期间，NPC 可能选择筹资购丹；合资到期、委托到期与灵圃生长按确定性时间规则结算，培养不冻结既有约定。模型离线或失败时可用“静修一旬”继续培养，NPC 不会套用旧剧情脚本。斗法中不可操作灵圃或推进旬数。培养、灵液、自动化开关和未收取产物随存档保存，重启后继续；重开此局会一起重置。

灵圃沿用 `POST /api/action` 与 `expectedRevision`，新增 `discover_bottle`、`plant_herb`、`water_herb`、`harvest_garden`、`buy_spirit_soil`、`enable_auto_water` / `disable_auto_water`、`enable_auto_plant` / `disable_auto_plant`。数量、价格和产量由服务端决定，输入中的额外数值不能改写结果。`view.garden` 返回神器状态、灵液、灵畦进度、待取收成和自动化设置。AI 能查看这些公开事实并讨论培养，但交谈本身不能获得神器或产物。

灵圃测试覆盖旧档迁移、只读预览、自动留种、异地培养、手动催熟、蓄液上限、息壤扩建、资源不足、重复收取、战斗限制、重启恢复与过期请求拒绝。

## 黄枫谷与血色禁地

完成太南小会后，在黄枫谷山门凭升仙令登记入门，再前往百药园接差事、潜修至炼气十一层。随后可报名血色禁地，采集紫猴花、玉髓芝，与南宫婉相遇并合力应对墨蛟，取得天灵果后回宗交药，领取筑基丹。任务药囊与普通灵草分开保存，卖草、委托不会消耗任务主药。

坊市取丹仍由模型依据当前资产和偏好自主规划，禁地交药提供独立的一枚筑基丹。坊市丹药归属变化不会切断主线，已有债务仍需偿还。若通过交易等途径先行筑基，可以直接拜师；已经进入禁地的炼气弟子须先携药离开才能闭关。筑基后回黄枫谷拜师李化元，获得青元剑诀。

陈巧倩、向之礼可以自行花费 20 灵石整理试炼见闻；需已经进入禁地、对玩家信任达到 10 且本人有足够资金。菡云芝可先通过真实委托收到灵草，再自主用一株救治试炼伤者。人物行动不能替玩家采药、交药或授予修为；多人选择同一援助时只扣一次资源。

新经历在 `campaign.storyFlags` 中记录事件 ID；`campaign.questHerbs` 保存任务主药。旧 `campaign.flags`、结局、余款、矿石和历史保留，不再驱动当前主线。原有替代丹按一枚筑基丹继续使用，不补发。没有升仙令的旧旅人可先通过拜帖审阅加入黄枫谷，再登记主线；已有其他门籍者须自行处理退出。

旅行仍使用 `/api/action` 的 `travel_region`：`river` 为百药园，`quarry` 为禁地外层，`ruins` 为中心区。进入分别需要黄枫谷登记、禁地报名和实际进入禁地，不能通过客户端参数跳过。原著地名的显示更新不更改旧存档的区域 ID。

当前主线可玩至筑基拜师；炼气为十三层，后续境界使用筑基、结丹、元婴、化神、炼虚、合体、大乘与渡劫飞升。高境界只定义术语，尚未开放相应章节。主线交锋仍采用注明气血代价的叙事结算。

拜师流程：到接引人所在区域 → 写下 1～160 字拜师缘由 → 递帖 → 接引人 Agent 根据门规、性格与已知经历邀请、婉拒或暂缓 → 获邀后玩家确认入门。模型未连接、超时或回应无效时保留待审拜帖，可重试或撤回，不能凭空批准。聊天中的口头承诺不会直接授予身份。同一时间只可有一个门派、一份待处理拜帖；退出需在面板再次确认，之后可另投门庭。

入门身份随存档保存，退出后往事仍留在记忆与邸报中。入门不赠送战力、物品、灵石，不重置功法、旧债或任务结果；主线拜师李化元会获得青元剑诀；贡献商店与门派战争尚未开放。

`POST /api/sects` 接受 `{type:"apply"|"review"|"join"|"withdraw"|"leave", sectId, reason?, expectedRevision}`；`reason` 仅递帖必填。递帖、审阅、确认入门需与对应接引人同区域；尚未离开斗法时不能处理门派事务。非法动作返回 400，旧版本返回 409；模型失败返回已保存的待审状态与来源。成功写入后返回新 `view`。`view.sects` 包含玩家身份、入门旬数、拜帖与门派目录，`people[].affiliation`、`roamers[].affiliation` 为派生公开身份。

测试覆盖旧档迁移、道统与记忆隔离、Agent 邀请/婉拒/暂缓/失败、确认入门与退出、版本防重、重启恢复、非线性传送、修为校验与山门模型的落点/建筑碰撞。

## 统一入口与目录

在项目根目录执行 `npm ci`、`npm start`、`npm test`。根目录 `index.html` 是唯一游戏页面，`server.js` 启动同一个服务；剧情、AI、人物、装备、斗法、灵圃、宗门与游历共用状态与存档。`game/` 仅是源码目录，不是另一个版本。

旧 `/mvp/` 书签自动跳转首页。新安装的存档在根目录 `.data/save.json`；升级时若根目录尚无存档，会继续读写原 `mvp/.data/save.json`，不复制出另一份进度。根目录 `.env.local` 优先；尚未迁移配置时兼容读取原 `mvp/.env.local`。已有进程环境变量优先于文件，`SAVE_PATH` 始终优先于默认存档路径。模型密钥与存档都不通过静态资源接口暴露。


## 原著宗门与房屋进入

当前四座山门使用《凡人修仙传》小说中的黄枫谷、掩月宗、魔焰门、鬼灵门，资料与适配范围见 [宗门资料依据](SECT_CANON.md)。这里的“正道”是越国七派一侧的游戏筛选标签，并非原著天南正道盟。旧自创门派的内部编号保持不变，已加入身份、拜帖/邀请、资源和剧情结果沿用原档；NPC 静态身份更新为对应的原著人物。其他原有沙盒人物不再被强加为原著宗门门人。

点击房屋、门牌可自动绕到门洞进入；门外靠近后也可以按 F。室内自动隐藏屋顶与高墙，显示家具和低墙；点击地板或用方向键行走，点击“离开房屋”沿门洞出门。家具和墙仍有碰撞。神手谷药庐、墨府内堂的任务点在室内，任务追踪先走入屋内再交互。跨区域仍直接传送，入屋不额外扣费或推进旬数。

若拜帖提示 **模型服务额度不足或计费不可用（HTTP 402）**，这不是宗门拒绝。检查当前 Key 所属模型账户余额/计费配置，或配置可用 Key 并重启服务，再点“再请接引人审阅”。重复递帖或单纯重启不能修复余额问题。失败时保留拜帖，不发放邀请；权限、限流、超时和无效回复会显示各自的处理提示。接口 `view.sects.application.failureReason` 为可选字段，成功审阅后清除。

建筑的可通行门口通向室内，可步行探索并使用室内任务点；神手谷药庐与墨府内堂的主线继续在对应房间内进行。室内外移动不替代剧情行动与战斗结算。
