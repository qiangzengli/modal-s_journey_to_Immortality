# 高精度角色 GLB 接入指南

本指南面向模型制作、客户端开发和发布维护人员。当前 `game/assets/characters/models/manifest.json` 为空：游戏仍显示现有程序模型。接口和验收工具已经具备，但仓库尚无达到参考图精度的完整角色 GLB；接入能力不代表视觉质量已达标。

人物仍按《凡人修仙传》天南／血色禁地时期制作。韩立保留浅色短袖外衫与护腕，南宫婉保留浅紫衣装。用户参考图只用于说明精细程度，不作为改装、换色或更换角色的依据。

## 最短接入流程

1. 在 Blender 或其他建模工具完成角色网格、骨骼、蒙皮、PBR 贴图和原地动作，导出一个自包含的 `.glb` 文件。
2. 运行 `npm run preview:characters`，打开 `http://127.0.0.1:4196/`。选择角色，打开「资源接入」，选择本地文件，核对左右臂、武器、位移根节点以及动作片段映射。
3. 点击「应用到当前角色」。检查正面、三分之四、侧面、背面、近景及上方动作列表。导入仅存在于这个浏览器页面，不上传文件、不读写游戏存档；「恢复项目模型」恢复清单配置。
4. 点击「导出角色配置」。将文件放入 `game/assets/characters/models/`，将导出的 **单个角色条目合并** 到同目录 `manifest.json` 的 `characters` 下，保留已有角色。不要直接覆盖其他人的条目。
5. 执行 `npm run check:characters` 和 `npm test`。重启游戏服务后刷新浏览器，在实际地图和斗法空间验收，再随代码一起发布。

预览工具默认端口为 4196，也可用 `PORT=4199 npm run preview:characters`。只绑定 `127.0.0.1`，不作为生产页面发布。

## version 1 清单

以下是配置格式示例，文件名和节点名称需要与实际资源对应；不是仓库已有的成品资产：

```json
{
  "version": 1,
  "characters": {
    "player": {
      "file": "hanli-tiannan-v1.glb",
      "height": 2.6,
      "rotationY": 0,
      "joints": { "leftArm": "LeftArm", "rightArm": "RightArm" },
      "weapon": "SwordBlade",
      "rootMotion": "Hips",
      "clips": {
        "idle": "Idle",
        "walk": "Walk",
        "attack": "Slash",
        "cast": "Cast",
        "guard": "Guard",
        "hit": "Hit",
        "defeat": "Defeat"
      }
    }
  }
}
```

| 字段 | 约定 |
| --- | --- |
| 角色 ID | 现有游戏 ID，例如 `player` 韩立、`ji` 南宫婉、`modafu` 墨大夫、`wen` 王蝉。未登记角色继续使用程序模型；墨蛟走独立妖兽入口。 |
| `file` | 模型目录内的文件名，只允许小写英文、数字、短横线、下划线和 `.glb` 后缀；禁止 URL、路径和查询参数。换版本时建议换文件名。 |
| `height` | 模型归一化后的高度，1–4 个世界单位。模型最低点自动对齐地面，横向中心自动居中。 |
| `rotationY` | 朝向修正，单位为弧度，范围 ±2π。预览面板以度数输入，导出自动换算。 |
| `joints` | 必填且不同的左右上臂节点，使用 GLB 原始名称。名称必须唯一；兼容 GLTFLoader 对冒号等字符的内部重命名。 |
| `weapon` | 可被装备灵光染色的武器网格或包含网格的组。韩立必填，其他角色可选。建议只映射剑刃或需要染色的部分。 |
| `rootMotion` | 可选。每帧把该节点的 X/Z 平移恢复为绑定值，防止动画和游戏位移叠加；Y 位移保留。仍建议导出原地动作。 |
| `clips` | 可选语义映射，片段名称必须唯一。只支持表中列出的 7 种动作。没有映射的动作使用现有手臂／武器旋转兜底。 |

导出人物正面朝 +Z、Y 向上，确保左右臂局部 Z 轴旋转能合理抬臂；否则应提供各动作的原生动画片段。映射不是自动重定向系统，不能修复错误蒙皮或不相容的关节轴。武器应绑定在正确手部层级。站立姿态的场景边界用于归一化，不应混入展示底座、相机道具或远离人物的辅助网格。

`idle` / `walk` 循环播放；攻击、防御、受击等按已有战斗进度采样；死亡停在最后一帧。目前不做动作交叉淡化和面部表情驱动。地图位置、冲刺位移和受击倾斜仍由游戏外层控制。

## 文件与性能约束

- 单文件 ≤ 32 MiB、≤ 150,000 个三角面、≤ 16 个材质。多个场景实例的实际三角面数还会在加载后再次检查。
- glTF 2.0 二进制 GLB，三角形拓扑。全部缓冲区和贴图必须嵌入文件；推荐 PNG/JPEG PBR 基础色、法线、粗糙度／金属度贴图，按模型需要控制贴图尺寸。
- 本版本未配置 Draco、Meshopt 或 KTX2/BasisU 解码器；请导出未压缩网格和普通贴图。第三方模型应先在制作工具中检查并转换。
- GLTFLoader 和 SkeletonUtils 与项目 Three.js 使用同一锁定版本。加载最多并行两份，不会请求额外 CDN。
- 预算是防止异常资源进入运行时的上限，不是多角色同屏性能保证。需要按实际设备降低面数、材质数与贴图开销；当前没有自动 LOD 或 GPU 纹理压缩。

CLI 先检查文件结构、路径、预算和映射，不能代替完整的 Khronos glTF 校验器、真实加载测试或人工美术验收。

## 运行时边界与生命周期

`createCultivatorActor` 仍同步返回原角色；`body / leftArm / rightArm / weapon / bag / nameplate` 等外部接口保留。GLB 通过异步加载成为 `body` 的可视子节点，完全验证成功后才隐藏旧可视模型。移动和战斗代码先写原有动作句柄，随后 `updateCharacterAsset(actor, frame)` 把语义动作、武器染色和受击闪光同步到 GLB。

不同角色克隆独立骨骼和材质，共享不可变几何与贴图；同文件只加载、解析一次。失败不隐藏原人物；替换失败保留上一份有效模型。旧请求不会覆盖新请求，销毁后晚到的加载不会重新挂载。

状态可在 `actor.userData.characterAsset` 检查：`procedural / loading / ready / fallback`，附 `file`、错误代码及消息；`characterAssetReady` 是首次清单加载的 Promise。预览面板显示这些状态。调用 `disposeCharacterAsset()` 释放该角色的独立资源并恢复程序模型；资源管理器 `dispose()` 关闭队列并释放缓存模板。游戏内角色是长期驻留对象；新建临时角色的调用方必须在移除时调用销毁方法。

清单和加载器在页面内缓存，服务端 GLB 白名单在启动时读取。修改清单或修复首次清单／加载器网络失败后，**重启服务并刷新页面**。初始加载超时为 15 秒。模型接入不会改变战斗数值、存档格式或模型问答配置。

## 部署与排错

生产仍通过 `/niminglu/` 访问；浏览器路径和 import map 相对应用入口解析。服务器只公开清单列出的 GLB、运行时模块和明确列出的 Three.js 插件，不提供目录浏览；未登记文件、缺失文件及越出模型目录的符号链接返回 404。

发布前将 GLB 与清单纳入同一个提交，并在待发布目录执行 `npm run check:characters`。失败时停止发布，修正后再验收。空清单是合法状态，命令会明确报告仍使用程序模型。

| 症状 / 代码 | 排查与处理 |
| --- | --- |
| 仍是程序模型 | 确认角色 ID 已登记、资源随发布打包；重启服务并刷新页面。空清单不触发 GLB 请求。 |
| `ASSET_HTTP_ERROR` | 检查资源 404、服务白名单和 `/niminglu/` 代理路径；先运行 CLI。 |
| `GLB_EXTERNAL_RESOURCE` | 重新导出，将贴图和缓冲区嵌入 GLB。 |
| `GLB_DECODER_REQUIRED` | 改用未压缩导出；当前没有相应解码器。 |
| `RIG_NODE_MISSING` / `CLIP_MISSING` | 对照实际 GLB 节点／片段名称，确保唯一且位于默认场景。 |
| `GLB_BUDGET_EXCEEDED` / `GLB_BOUNDS_INVALID` | 检查面数、材质、实例重复以及远离角色的辅助网格。 |
| `ASSET_LOAD_FAILED` | 文件结构检查通过但 Three.js 无法加载；检查错误消息，在制作工具及完整 glTF 校验器中验证资源。 |
| 角色滑步或攻击方向异常 | 使用原地动画、修正朝向、检查关节局部轴及动作映射。 |

回退某个角色时移除该角色清单条目，重启并刷新即可恢复程序模型；也可回退整个代码版本。均不需要修改或覆盖玩家存档。
