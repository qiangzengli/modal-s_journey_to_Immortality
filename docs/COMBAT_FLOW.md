# 斗法即时反馈与后台战术

目标：模型慢、失败或无响应时，开战和每次出招仍可立即完成规则结算、保存并展示战报；继续保留 Agent 敌方战术，完成后发布到 `/niminglu/`。

- `/api/combat` 与主线开战行动不再等待模型。响应完成真实结算与原子存档，伤害、消耗、胜负、奖励规则不变。
- 开战和读入进行中的战斗会在后台请求短期条件战术。同一场战斗最多一个请求，8 秒内终止；失败退避 10 秒，下次行动可重试，不重复堆积请求。
- 模型决定通常、己方重伤、玩家低血、玩家低真气四种情境的行为。规则按当前状态选择，避免快速操作时旧血量决策被当成当前事实。从计划返回的回合起，每隔两回合尝试更新，最多沿用六回合；未就绪/过期时明确采用基础试探进攻，不冻结操作。
- 回合响应中的 `battle.agentIntent` 是下一次敌方回应的固定预告；后台结果不能在玩家选择期间改掉已展示的招式。新战术仅在下一次回合结算后准备后续预告，不追溯改变任何战报。
- 后台模型只写运行时缓存，不能写存档、加版本或占用行动锁。结束战斗、离场、重开时取消未完成请求；旧战斗的迟到结果不得进入新战斗。
- 存档保存实际待执行招式；服务器重启时原招式和战斗状态保持不变，后台重新准备后续战术。不公开原始计划，不信任客户端传入的战术或伤害。
- 页面收到结果立即更新气血和战报，再播放约 0.5～1.7 秒的交锋动画（视法术与协战而异）。动画期间防止连点重复提交；动画结束立即恢复出招。去掉战场中央通用结算遮挡；实际网络较慢时在回合标题提示同步状态。

验收：模型请求悬而未决时开战、连续出招、读取状态仍及时响应；回合预告与实际结算一致；模型计划在后续回合生效；重复/过期提交不重复消耗；超时、非法计划、战败、逃跑、同敌重战、重启均不串档。部署前保留服务器活跃战斗并备份存档和模型配置。
