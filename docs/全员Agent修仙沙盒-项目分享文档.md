# 全员 Agent 修仙沙盒｜项目分享文档

> 暂定名：《逆命录》
>
> 文档性质：供组内讨论的产品提案，不代表已确定的开发计划或已实现功能。
>
> 核心命题：如果修真界里的每个人都记得自己的遭遇、追求自己的目标，并会根据有限的信息改变行动，玩家会怎样活下去？

## 1. 一页摘要

**一句话介绍：**玩家进入一个资源稀缺、消息真假难辨的修真世界。修士、商人和宗门人物都有自己的目标、关系与记忆。玩家可以交易、谈判、布局、闭关和斗法；世界会记住这些行为，并在玩家不在场时继续变化。

我们希望玩家获得的体验，不是“和很多会聊天的 NPC 对话”，而是**做一件事，看到不同的人因各自利益作出反应，再承担后果**。例如玩家放出一条秘境消息，急需灵药的散修可能冒险前往，宗门执事可能封锁入口，而曾被玩家欺骗的商人可能借机揭穿消息来源。每一步都应该能追溯到人物的所知、所求和所能。

| 项目要点 | 暂定方向 |
| --- | --- |
| 类型 | 单人、回合推进的修仙策略角色扮演沙盒 |
| 核心乐趣 | 信息博弈、长期因果、在有限资源下寻找出路 |
| 核心差异 | NPC 有持续目标和有限认知；传闻、契约与人际关系推动世界演化 |
| 玩家输入 | 常规操作用明确按钮；关键交涉与计策允许自然语言 |
| 规则底座 | 世界状态、资源、战斗结果由可验证的游戏规则决定；模型负责理解意图、选择行动和表达 |
| 首个验证场景 | 一处地下坊市、一片城外险地、约 8 名关键人物、一次可争夺的机缘 |
| 当前阶段 | 立项讨论；玩法、成本、技术可行性均待原型验证 |

**建议的立项原则：**先证明“可追溯的因果”有趣，再扩地图、人数和视觉表现。我们可以把“全员 Agent”理解为**每个重要人物都能持续自主行动**，不等于每个人每个回合都调用大模型。

## 2. 玩家究竟在玩什么

### 2.1 三个体验支柱

1. **众生有算盘。**人物会为灵石、寿元、师门、道侣或旧怨行动；同一事件对不同人物有不同意义。没有永久固定的“任务 NPC”。
2. **消息有来路。**角色只根据自己亲历、听闻或推断的事行动。谣言会沿交易、师门和传音网络传播，也可能在传播中变形。玩家能够调查来源、伪造证据或控制消息扩散。
3. **算计要付代价。**话术可以改变对方的判断，却不能凭一句话创造物品、抹掉仇恨或越级秒杀。计策要消耗时间、物资、信誉，并接受失败风险。

### 2.2 一个五分钟的游玩例子

玩家在坊市听说一枚筑基丹即将被私下出售，自己又缺灵石。玩家有三种思路：

- **交易：**查证丹药真伪，找急需丹药的修士合资竞买，约定分成。
- **布局：**向执事提供走私线索，换取查封时的优先购买权；被揭穿则失去坊市信用。
- **夺宝：**在城外设伏，但目标可能先把丹药交给同门，战斗胜利也未必拿到丹药。

玩家选择伪造一张“丹药有毒”的鉴定符。药师因声誉风险撤出竞价，走私商人降价卖给另一名散修。数月后，散修凭此丹突破，发现当年的假鉴定，开始追查伪造者。玩家在《修真邸报》里读到突破消息，在坊市里看见商人开始回避自己。**故事来自规则、信息和人物动机的碰撞；文本只是呈现方式。**

### 2.3 单局循环

```text
观察局势 → 选定目标 → 收集信息 / 交换资源 → 交涉或行动
    ↓                                      ↓
查看新的机会 ← 查看邸报与人物变化 ← 世界按旬或月结算
```

短循环是一次交易、交涉或遭遇；中循环是一次机缘争夺；长循环是突破境界、维系关系与应对寿元。闭关是主动推进世界时间的选择：收益是修为，风险是错过机缘以及让对手完成布局。

## 3. 核心系统设计

### 3.1 人物与关系

每名关键人物拥有可变的状态：修为、寿元、资产、当前位置、可执行行动、长期目标、短期需求，以及与其他人的关系。性格不是固定台词标签，而是**决策倾向**：同样缺灵石，谨慎的药师会求稳出售药材，激进的劫修可能盯上买家。

关系至少区分信任、利益、恩怨、承诺四类。一次背叛不必直接将“好感”减到负数，它可能导致撤资、向他人泄密或改变结盟条件。重要人物应允许生存、退让、失败和反悔，避免全员只会敌对。

### 3.2 记忆、传闻与因果账本

世界保留两种记录：**事实事件**和**角色所知**。事实记录“谁在何时做了什么”；角色所知记录“谁从哪里听到什么，以及有多相信”。二者可以不一致。每条重要传闻可带来源、时间、可信度、传播范围和失真程度。

玩家看到的是邸报、线索、目击证词和关系变化，不会直接读到所有 NPC 的私密意图。高阶探查只能揭示有依据的线索，并可能被对方察觉。为避免“AI 随口编出一段因果”，重要结果须能回溯到事件账本：**哪条消息使谁改变了哪项决策**。

### 3.3 自然语言交涉与自由计策

自由输入应聚焦在少数高价值场景：谈价、说服、威胁、试探、立约、设伏和传音。系统先把话语解释成可执行意图，例如“报价 200 灵石并承诺事后补偿”，再检查人物是否知道相关事实、玩家是否拥有承诺的资源、对方是否有接受的理由。玩家仍可撒谎；**撒谎是游戏内行动，不是修改游戏事实的指令**。

交互反馈要指出关键依据，例如“他不信你，因为你拿不出药师印记”，并给玩家继续准备的空间。无法识别的输入应引导玩家改述或提供可用行动，不让对话卡死。

### 3.4 经济、寿元与机缘

灵石、丹药、情报、时间和信誉都是资源。机缘数量有限，玩家与 NPC 会争夺，但不能只靠抢夺取胜。寿元提供长线压力；闭关、炼丹、经商、结盟和冒险是有不同成本的突破路径。

建议先把经济做成小型闭环：药材来源 → 炼丹与出售 → 需求者购买 → 价格和人物行动变化。这样物价波动能反映世界事件，而非完全随机刷新。

### 3.5 斗法与构筑

战斗保留清晰的回合制规则：行动顺序、灵力、护体、符箓、法宝和环境。语言能提出战术，例如假装退走、诱敌踏阵，但是否成功取决于准备、位置、消耗品和对手状态。玩家应在行动前知道主要风险，在结算后知道胜负依据。

“魂幡 / 器灵”可作为中后期构筑方向：有名有姓的人物死亡后，其生前功法与执念影响可炼制的能力。这个系统涉及大量内容、平衡和叙事工作，首版只需验证一件因果明确的战利品。夺舍与重生同样留到核心循环成立后再评估。

## 4. 为什么需要 Agent，以及如何控制它

### 4.1 权责边界

**游戏规则拥有最终裁定权。**模型可以提出“某修士决定逃跑”“玩家试图以假消息压价”，但不能直接写入金钱、伤害、物品归属或死亡结果。建议的处理顺序是：

1. 从玩家输入或 NPC 目标中提取候选行动。
2. 检查行动前提：知识、位置、物品、时间、关系和权限。
3. 用游戏规则结算成功率、资源变化与后果。
4. 写入事件账本与角色所知，再生成符合结果的对话和邸报。

例如“引爆三张天雷符”必须先查背包和布置位置；模型不能自行给出伤害倍率。失败也要有可玩结果：符箓失效、对方察觉或玩家获得新的线索，而不是一句笼统的“不合理”。

### 4.2 分层调度

| 层级 | 用途 | 建议运行方式 |
| --- | --- | --- |
| 在场人物 | 玩家正在交涉、追踪或斗法的少数人物 | 关键回合调用模型，生成候选行动和对话 |
| 活跃人物 | 与当前机缘、宗门或玩家关系密切的人物 | 在时间推进或重大事件时作目标评估；能用规则结算的就不调用模型 |
| 背景人物 | 普通商贩、散修与环境群体 | 按日程、供需和简单策略运行；进入关键事件后再提升处理等级 |

分层是一种**计算调度**，不是人物智力分层。预算应按“每名玩家每小时的模型调用量 × 平均输入输出量 × 模型单价”实测，再决定人物规模。多人打包推演可能降低调用开销，但会增加秘密串线、状态冲突和重试成本；是否使用要通过实验验证。

### 4.3 记忆与可复现性

首版优先使用结构化事件和少量重要记忆，不预设向量库。只有当检索质量和数据量确实需要时，再引入语义检索。每次调用记录输入的世界状态版本、人物可见信息、模型返回的候选行动、规则裁定和最终事件。固定随机种子与存档快照，让团队能复盘“为什么这名修士突然背刺”。

对话、传闻和玩家文本都按**游戏数据**处理，不能成为修改世界规则或读取其他角色秘密的系统指令。模型超时或失败时，关键行动回退到规则选项，游戏仍可继续。这个边界同时保护公平性、成本和可调试性。

## 5. 首个 Demo：地下坊市的一场机缘

### 范围

只做一处坊市、一片城外险地、一枚有争议的筑基丹、玩家和约 8 名关系相连的人物。人物不求多，求每个人在这枚丹药上有不同的利害：卖家急需灵石、药师担心假药、散修临近寿元关口、执事关注走私、劫修等待落单买家。

首版必须跑通四件事：

1. 玩家通过交易、调查或交涉取得一条可验证的信息。
2. 玩家用自然语言提出一次非常规但合理的计划，系统把它转成可裁定行动。
3. 至少两名人物根据各自所知与目标改变后续行动。
4. 推进一旬后，邸报、人物位置和资源账目能展示该计划的后果，并解释其来龙去脉。

建议提供三条能通关的路线：**谈成交易、借势布局、正面争夺**。它们都应付出不同代价，不能只换一段不同文案。第一版暂缓大地图、百人生态、完整魂幡、夺舍、TTS、复杂美术以及多平台同步开发。

### 验收方式

组织小规模盲测，让体验者在不了解底层规则的情况下玩同一局初始盘面。记录以下问题，不把目标数字当作现成事实：

| 要验证的问题 | 建议观察方法 |
| --- | --- |
| 玩家是否理解自己为什么成功或失败？ | 结束后让玩家复述两次关键裁定的依据，对照事件账本 |
| 人物是否显得有目标，而不只是会说话？ | 让玩家说出至少两名人物的诉求和一次自主行动 |
| 自由输入是否真正改变玩法？ | 对比按钮路线与自由计策路线的状态变化，而非只对比文案 |
| 世界是否连续且公平？ | 检查人物是否使用了未知情报、物品是否凭空增减、承诺是否被记住 |
| 成本和等待是否可接受？ | 记录每局调用次数、实际费用、每次等待时长与超时回退次数 |

**继续投入的判据：**玩家愿意尝试第二种解法，能讲清至少一条“我的行为 → 别人的反应 → 新局面”的因果链；同时工程团队能稳定复现和修正违背规则的事件。若只能得到有趣对白，需回到规则与人物动机设计，而不是扩大模型规模。

## 6. 开发路径与团队分工建议

以下是以小团队制作可玩切片为前提的顺序，具体排期在工作量评估后确定。

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| A. 纸面规则与事件样例 | 8 名人物卡、关系图、坊市资源账、3 条玩家路线 | 同一事件能手工推演，规则没有明显自相矛盾 |
| B. 规则原型 | 时间推进、行动校验、交易和事件账本 | 不调用模型也能跑完一局，并能复盘结果 |
| C. Agent 接入 | 交涉解析、人物候选行动、生成邸报、失败回退 | 自由输入能改变合法行动；没有越权改写世界状态 |
| D. 体验验证 | 可玩的单局 Demo、日志与盲测报告 | 找到可重复的乐趣和明确的改进清单 |

产品 / 叙事负责人物目标与选择后果；系统策划负责资源、战斗与裁定；AI 工程负责上下文、结构化输出和观测；客户端负责可读的局势界面；测试负责破坏规则的输入与长期存档验证。人数少时可兼任，但这些责任需要有人明确承担。

## 7. 商业化与产品边界

首个 Demo 不应把“模型调用次数”包装成影响胜负的付费资源。可以设计游戏内的**神识**作为侦查或施展特殊能力的玩法资源，但它与真实 API 费用应分开计算，避免玩家为了省钱不敢使用核心玩法。

商业模式待留存和真实成本明确后选择：买断并含一定在线额度、可选自带模型服务，或提供离线规则模式。BYOK 会带来密钥存储、配置体验和不同模型效果一致性问题；本地模型也需验证设备性能，不能提前当作普遍可用的成本解法。

世界观、人物、地名、法宝和视觉资产应建立原创设定。可以借鉴修仙题材的生存压力与博弈感，不直接使用已有作品的人物、剧情或标志性设计作为对外产品内容。

## 8. 本次会议建议拍板的三件事

1. **玩家主乐趣：**更重信息与人际布局，还是更重回合斗法？建议 Demo 前者为主，斗法负责兑现计划的风险。
2. **首版表现形式：**以案牍 / 坊市面板突出人、消息和账本，还是先做可探索地图？建议先验证信息可读性，再决定地图投入。
3. **最小成功标准：**团队是否接受“8 名人物 + 1 枚丹药 + 3 条路线”作为第一阶段范围，以及上文的因果、稳定性和成本验收方式？

**建议的分享顺序（10 分钟）：**1 分钟讲核心命题，2 分钟讲坊市案例，3 分钟讲玩法闭环，2 分钟讲规则与 Agent 的边界，2 分钟讨论 Demo 范围。讨论时先判断核心体验是否值得做，再讨论平台、美术与商业化。

**希望团队最终回答的问题：**当玩家说“我想用一个谎言换来筑基机会”，我们能否让世界给出有逻辑、可追溯、值得再玩一次的回应？
