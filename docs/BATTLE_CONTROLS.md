# 斗法视角与自动战斗

需求：斗法场景可以旋转，从不同角度查看人物；增加自动战斗，根据当前血量、功法和物品，通过 AI 尽量降低获胜消耗。与独立队伍回合兼容，模型调用不能阻塞出招。

## 操作

- 空白场景拖动可 360° 环绕、上下调整俯仰；滚轮或双指缩放。Q / E 左右转向。视角区域获得焦点后，方向键调整、加减号缩放、Home 复位。
- 顶部按钮提供旋转、缩放、复位以及全景／主角／对手聚焦；战报可收起，方便查看完整模型。
- 同一场斗法保留镜头；出招、结算、窗口变化均不复位。退出战斗后再次开战使用默认镜头，地图镜头独立。
- 点击「自动战斗」开始，点击「停止自动」随时接管。已发送的一招仍按正常规则完成，随后不再自动出招。页面隐藏、战斗结束或请求失败会停止，刷新后不自动恢复。
- 每次行动都重新读取最新血量、真气、冷却、库存和队员行动资格。胜利后等待玩家确认战利品，不代替玩家领取剧情奖励或开始下一战。

## 消耗策略

默认「节省优先」：优先普攻、功法；普通回复药仅在危险时考虑，保留阵法与稀有物品。「不使用物品」禁止所有消耗品；「胜利优先」允许必要的战斗丹药与阵法。策略在启动前选择，运行中停止后才能调整。

规则根据保守伤害估计、护罩、预告反击、治疗收益、真气和物品代价选择行动；普攻足以收尾时优先普攻。无法找到能承受当前反击的合法招式时暂停，连续无进展或超过 100 次行动也会暂停。随机伤害与对手变招使全局最小消耗无法保证，界面不承诺必胜。

AI 在后台生成条件策略：疗伤阈值、真气保留量、偏好功法和重击应对。每场最多一个规划请求在途，每隔至少三回合更新一次；策略到达后最多使用六回合。模型不可改写库存、伤害或物品权限。等待／离线／失败时使用本地应对，并显示来源，不等待模型再出招。

## 接口

`POST /api/combat/auto-plan`，JSON：`{expectedRevision, enemyId, policy}`。沿用同源访问约束；有效进行中战斗与版本必须匹配。200 返回 `{source, plan, enemyId, revision, modelName}`，source 为 model/offline/unavailable；无效参数或非进行中战斗 400，过期版本或敌人不匹配 409，内容类型错误 415。

此接口只读、不占行动锁、不写存档。同场同策略并发规划合并，切换战斗时取消旧缓存；客户端停止或新战斗会丢弃迟到结果。真正出招仍使用 `/api/combat` 的 `turn`、`actorId` 与 `expectedRevision`，沿用服务端战斗校验和原子存档。

## 验证

自动化覆盖相机保留与边界、鼠标／触摸取消、输入框快捷键隔离、零物品胜利、队员轮流出招、濒危补给、冷却／库存约束、模型输出白名单、模型挂起时 HTTP 回合正常结算、自动停止和迟到结果隔离。浏览器另验旋转、缩放、复位、收起战报与自动交锋。
